# Nexus Roulette

Telegram мини-апп для компьютерного клуба: клиент сканирует QR на ресепшене,
крутит рулетку и забирает приз на стойке. Владелец видит в приложении, что
выигрывают, что забирают и что сгорает.

## Как это работает

**Клиент.** Наводит камеру на наклейку с QR → открывается Telegram → сразу
открывается рулетка с уже начисленным прокрутом. Ни диктовать ID, ни ждать
сотрудника не нужно. Выигранный приз лежит во вкладке «Призы» с кодом; код
показывается сотруднику на стойке.

**Сотрудник.** Присылает боту код `NX-XXXXXXXX` — приз гасится. Может начислить
прокрут вручную, прислав числовой ID или `@юзернейм` клиента, если что-то пошло
не так со сканированием.

**Владелец.** Вкладка «Админ» внутри приложения: отчёт с воронкой по каждому
призу, редактор призов и весов, база клиентов, персонал и настройки.

## Устройство

| Файл | Зачем |
|---|---|
| `schema.sql` | Вся база: таблицы и SQL-функции. Выполняется в Supabase |
| `api/checkin.js` | Чек-ин по QR, начисляет прокрут |
| `api/spin.js` | Прокрут рулетки |
| `api/inventory.js` | Стартовое состояние приложения |
| `api/config.js` | Сектора колеса |
| `api/qr.js` | Генерация QR-кода наклейки |
| `api/webhook.js` | Бот: погашение кодов, ручное начисление |
| `api/admin/*` | Кабинет владельца |
| `lib/guard.js` | Проверка подписи Telegram и ролей |
| `qr.html` | Страница печати наклеек |

Критичные операции — списание прокрута, выбор приза, погашение кода — вынесены
в SQL-функции (`do_spin`, `do_checkin`, `do_redeem`). Каждая работает одной
транзакцией, поэтому двойной тап по кнопке не даёт двух призов, а два
сотрудника не могут погасить один код дважды.

## Настройка

### 1. База

Supabase → SQL Editor → New query → вставить `schema.sql` → Run.
Скрипт идемпотентный, повторный запуск ничего не сломает.

В строке с `insert into staff` укажите свой Telegram ID (узнать: команда `/id`
в боте) — это владелец, которому видна вкладка «Админ».

### 2. Переменные окружения в Vercel

Settings → Environment Variables:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен бота от BotFather |
| `WEBAPP_URL` | адрес деплоя, например `https://nexuscyberclub.vercel.app` |
| `SUPABASE_URL` | Supabase → Settings → API → Project URL |
| `SUPABASE_SERVICE_KEY` | там же, ключ `service_role` |
| `OWNER_IDS` | *(необязательно)* запасной вход в кабинет, если таблица `staff` недоступна |

После добавления переменных нужен передеплой — Vercel подхватывает их только
при новой сборке.

### 3. Main Mini App в BotFather — обязательный шаг

Без этого ссылка `t.me/бот?startapp=...` откроет чат с ботом, а не приложение,
и QR работать не будет.

```
/mybots → выбрать бота → Bot Settings → Configure Mini App
→ Enable Mini App → указать адрес из WEBAPP_URL
```

### 4. Вебхук бота

Один раз открыть в браузере, подставив свои значения:

```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<WEBAPP_URL>/api/webhook
```

В ответе должно быть `"ok":true`.

### 5. Наклейка

Открыть `<WEBAPP_URL>/qr` в браузере, задать метку точки и распечатать.
Метка попадает в отчёт: сделайте разные наклейки для ресепшена (`r1`), столов
(`tables`) и листовок (`flyer`) — будет видно, какая реально приводит людей.

## Проверка после деплоя

1. Отсканировать QR камерой телефона → приложение открылось, прокрут доступен
2. Крутить → колесо останавливается на секторе выигранного приза
3. Отсканировать второй раз → нового прокрута нет, показано время до следующего
4. Быстрый двойной тап по «Крутить» → списывается ровно один прокрут
5. Прислать код боту → погашен; прислать его же повторно → «уже погашен»
6. Владелец видит вкладку «Админ», обычный клиент — нет
7. Поменять вес приза в кабинете → перезайти → сектор изменил ширину

## Настройка акции

Всё в кабинете, без правок кода и деплоя:

- **Вес** задаёт шанс выпадения приза. Приз выбирает сервер, лента лишь
  доезжает до его карточки — подкрутить результат с телефона нельзя.
- **Лимит в сутки** ограничивает выдачу дорогих призов — «не больше двух VIP
  в день» вместо надежды на теорию вероятностей.
- **Срок сгорания** — рычаг возврата: чем короче, тем быстрее клиент придёт,
  но тем больше призов сгорит зря. Смотрите на колонку «Сгорел» в отчёте.
- **Процент «Забрали»** — главный индикатор. Если призы выигрывают, но за ними
  не приходят, акция не работает: либо приз не нужен, либо срок слишком мал.
